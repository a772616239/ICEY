# 2026-10-19

## ICEY 角色状态机 → Mecanim 可行性勘察

**项目基线**：Unity 2020.3.49f1；Assets/AnimationClip 共 426 个 clip，其中 329 个 `m_Legacy: 1`，97 个非 legacy（供 Animator 驱动特效/UI/场景）。

**架构事实（代码验证）**：
- 状态机为自研泛型字符串状态机：`Scripts/StateMachine.cs`（挂在 GO 上，Update 派发 StateUpdate）+ `Scripts/ClassStateMachine.cs`（纯 C# 版）。28 个 `*Action.cs` 各自定义 `StateEnum`，合计 729 个状态；最大的 `PlayerAction.cs` 134 个状态，`DahalAction.cs` 57，`DaoPaoAction.cs` 47。
- 玩法能力层：14 个 `CharacterState` 子类（PlayerMove/Attack/Jump/Flash/Charge/Hurt/Execute 等），监听 OnEnter/OnExit/OnTransfer（`StateMachine.cs:126-142`）。
- 表现层（玩家）：`MultiSpineAnimationController.cs` 持有 6 个 `SkeletonAnimation`（Normal/Attack/SpAttack/Hurt/UpRising/HeavyAttack），按武器类型 HideSkeleton 切换；`Play()` 同时驱动 Spine `state.SetAnimation` 与 legacy `Animation.Play`。`PlayerAction.cs` 中 `msac.Play` 调用密集。
- Legacy clip 的曲线路径只有 `AtkBox` / `HurtBox` / `Body`——**打的是碰撞盒，不是骨骼**。骨骼动画全部在 Spine 里。
- Spine 运行时为 2.x 私有分支（存在 `SkinnedMeshAttachment`），**没有 SkeletonAnimator 实现**；`SkeletonUtility.cs:181`、`PlayerControllerDemo.cs:117`、`HeroDeath.cs:10` 三处 `GetComponent<SkeletonAnimator>()` 属死引用。
- 引用面：61 个 .cs 引用 StateMachine；`SetState(` 调用点 17 处。
- Animator 现状：`Assets/AnimatorController/` 有 80+ 个 controller，但只用于特效/门/UI/灯光（Flash_Distort、EnemyHitEffect、Warning 等），角色 prefab 无 `m_Controller`。

**结论**：不能"转换"。Mecanim 只能驱动 Transform 层级，Spine 骨骼是 Skeleton 内部数据（非 Transform），无迁移通道；把 729 个状态迁到 Animator state + StateMachineBehaviour 等于重写玩法逻辑（位移/无敌帧/攻击盒/弱点击破全在里面），收益为负。可行方向只有两个：① 生成只读的 .controller 镜像供可视化审查；② 原地重构（显式转移表 + 去字符串比较）。
